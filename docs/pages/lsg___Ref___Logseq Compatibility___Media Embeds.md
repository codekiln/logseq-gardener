- # Media Embeds Compatibility
	- `lsg` publishes Logseq's video embeds and YouTube timestamps: `{{video}}`, `{{youtube}}`, `{{vimeo}}` and `{{bilibili}}` become YouTube, Vimeo, Bilibili, Loom or plain players of Logseq's size and position, `{{youtube-timestamp}}` becomes a clock icon and a time such as `04:40` that seeks the video above it and plays, and video files play in a `<video>` element. It shows a click-to-load placeholder until the reader asks for the player, so no page contacts YouTube before a click; its timestamps are real links that work from the keyboard and without JavaScript; it honours `?t=` start times that Logseq ignores; and a timestamp seeks the nearest video before it in its own page's outline, also when the same video appears twice or the timestamp is copied into another page.
	  id:: 67acc7d1-0cd9-4189-819c-e216b53ae386
	- Measured on 2026-10-26 against the `gh-pages` build of the encode garden (`gh-pages` commit `8132c95`, served locally, light theme, 1280×800 and 390×844, Chromium with network access to YouTube) and an `lsg` build of garden commit `083106d` from `lsg` `48fcc54` (`mise run parity:build`, run `20261027T002614Z`). The OpenSpec change [match-logseq-media-embeds](https://github.com/codekiln/logseq-gardener/tree/main/openspec/changes/archive/2026-10-28-match-logseq-media-embeds) then built the players and timestamps, and [published-media-embeds](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/published-media-embeds/spec.md) holds their requirements; [published-dialogue-timestamps](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/published-dialogue-timestamps/spec.md) covers timestamps that seek audio recordings.
	- ## What Logseq's published site shows
		- Source links point at the local `logseq/og` checkout, `6e7afa8eb` (`frontend` = `src/main/frontend`). Measured live values come first and win where they differ from the checkout or from [[lsg/Ref/Logseq Published Site/Clickable Prototype]]. The live build is older than the checkout in one place: its YouTube iframe has neither `picture-in-picture; web-share` in `allow` nor `referrerpolicy`. The Prototype board differs from the live build in several places, listed where they occur: it draws a 560px 16:9 placeholder, gives the timestamp the title `Seek video`, shows a toast and a `Seeked to` badge, and limits seeking to videos on the same page.
		- The encode garden uses `{{video}}` 118 times in 113 files and `{{youtube-timestamp}}` 2,727 times in 54 files.
		- ### `{{video URL}}`
			- [`macro-video-cp`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/block.cljs#L1328-L1377) matches the URL against [`get-matched-video`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/util/text.cljs#L12-L23) (YouTube, Loom, Vimeo, Bilibili, in that order).
			- | URL | Player |
			  | --- | --- |
			  | `youtube.com`, `youtu.be`, `y2u.be` with an 11-character id | The YouTube player below, with `start` from `&t=` |
			  | `youtube.com` with an id of another length | An iframe whose `src` is the URL as written |
			  | `youtube-nocookie.com` | `https://www.youtube-nocookie.com/embed/<id>`, no start time, no seek |
			  | `loom.com/share/…` or `/embed/…` | `https://www.loom.com/embed/<id>` |
			  | `vimeo.com`, `player.vimeo.com` | `https://player.vimeo.com/video/<id>` |
			  | `bilibili.com/video/<bvid>` | `https://player.bilibili.com/player.html?bvid=<id>&high_quality=1&autoplay=0`, plus `&page=` from `?p=` |
			  | Any other URL | An iframe whose `src` is the URL as written |
			  | Not a URL | `span.warning.mr-1`, title `Invalid URL`, text `{{video …}}` |
			  | No argument | `span.warning.mr-1`, title `Empty URL`, text `{{video}}` |
			- **Start time.** Only `&t=(\d+)` is read ([`block.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/block.cljs#L1355-L1358)). `watch?v=TQsP_PlCY1I&t=205s` gives `start=205`. `youtu.be/yxi1O0T4l6k?t=14` and `?t=1m30s` give no start time (measured on `Art/Sound/Idea/Vocal/Tract Simulation with Motion Capture`). 4 garden pages use `youtu.be/…?t=`.
			- **Non-YouTube iframe.** `allowfullscreen`, `allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope"`, `framespacing="0"`, `frameborder="no"`, `border="0"`, `scrolling="no"`, `width` and `height` as for YouTube; Bilibili's height uses 360/560. Measured on `Atlassian/Blog/25/05/Introducing Atlassian's Remote Model Context Protocol`: an `.mp4` URL on another host becomes an iframe pointing at the file, 749×315.
			- **Paste.** Pasting a matching video URL in the editor wraps it in `{{video …}}` ([`paste.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/handler/paste.cljs#L49-L57)). A bare video URL in a page renders as an ordinary link.
		- ### The YouTube player
			- [`youtube-video`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/extensions/video/youtube.cljs#L45-L70) renders this markup.
			- ```html
			  <iframe id="youtube-player-6cqVzgVQJfE" allowfullscreen=""
			    allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope"
			    frameborder="0" src="https://www.youtube.com/embed/6cqVzgVQJfE?enablejsapi=1"
			    height="315" width="560"></iframe>
			  ```
			- **Wrapper.** The iframe sits inline in the block's content (`div.inline` or `div.is-paragraph` inside `.block-body`), with no wrapper of its own.
			- **Size.** `width` is `min(window width − 96, 560)` and `height` is `width × 315 / 560`, both fixed when the block renders. Logseq's base styles then set `iframe { width: 100%; margin: 1rem 0 }` ([`common.css`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/common.css#L129-L132)), so the iframe fills the block's width and keeps the attribute height. Measured: 718×315 on `Person/Omer Hamerman/YouTube/26/07/The Holy Grail of Code Review TUIs` at 1280px (749×315 one level shallower), not 560×315 and not 16:9; 239×165 at 390px (attributes 294×165). Margin `16px 0`.
			- **API.** Mounting the first player inserts `https://www.youtube.com/iframe_api` and registers a `YT.Player` for each iframe in `:youtube/players`, keyed by video id ([`youtube.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/extensions/video/youtube.cljs#L12-L43)). The API adds `title="<video title>"` to the iframe.
			- **Same video twice.** Both iframes get the same `id` (measured on `AI/ES/25/ws/What I Learned at the AI Engineer Summit Workshops 2025`, `youtube-player-TQsP_PlCY1I` twice), and the second registration replaces the first in the player map.
			- **Loading.** No `loading="lazy"` and no placeholder: the iframe loads as soon as Logseq renders its block.
		- ### `{{youtube URL}}`, `{{vimeo URL}}`, `{{bilibili URL}}`
			- `{{youtube}}` takes an 11-character id or a URL matching `youtube-regex` and renders the same player with no start time, even when the URL has `&t=` ([`block.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/block.cljs#L1488-L1495)).
			- `{{vimeo}}` and `{{bilibili}}` render the iframes from the table above ([`block.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/block.cljs#L1290-L1326)); Bilibili's height is at least 500px.
			- The encode garden uses none of the three.
		- ### `{{youtube-timestamp N}}`
			- **Argument.** Whole seconds (`620`), `M:SS` or `H:MM:SS`, with minutes and seconds 0–59 ([`parse-timestamp`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/extensions/video/youtube.cljs#L124-L140)). Any other argument renders nothing ([`block.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/block.cljs#L1497-L1500)).
			- **Display.** Two-digit `MM:SS`, with `HH:` only when the hour is not zero: `0` → `00:00`, `41` → `00:41`, `620` → `10:20`, `3600` → `01:00:00` ([`seconds->display`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/extensions/video/youtube.cljs#L72-L83)). Measured on the Omer Hamerman page: `00:00`, `00:41`, `01:46` … `15:26`.
			- **Markup.** `<a class="svg-small youtube-timestamp">` holding the 20×20 `clock` icon (`svg.h-5.w-5`, `fill="currentColor"`) and the time ([`youtube.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/extensions/video/youtube.cljs#L103-L111)). No `href`, no `title`, no role.
			- **Styles.** `.svg-small svg { transform: scale(0.6); display: inline }` ([`common.css`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/common.css#L557-L560)): the icon draws at 12×12. The link inherits the block's font size (16px; 19.2px in an `h3`), has no underline and a pointer cursor. Measured colour `rgb(52, 81, 178)`, different from page references (`#106ba3`); the rule that sets it was not traced and may come from the garden's `custom.css`.
			- **Keyboard.** An anchor without `href` is not focusable; measured `focus()` leaves it unfocused, so keyboard readers cannot seek.
			- **Seek.** A click stops the event and calls `seekTo(seconds, true)` on the player of the last YouTube iframe in the document that comes before the link ([`get-player`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/extensions/video/youtube.cljs#L85-L101)). The rule is document order, not the outline or the page: a timestamp in Linked References seeks whatever YouTube iframe precedes it on screen, and with a repeated video id it seeks the last registered player. If no YouTube player precedes the link, the click does nothing. Measured: clicking `04:40` before playing put the video at 282.9 s and playing.
			- **Elsewhere.** In block reference text, breadcrumbs and search results the timestamp is plain `MM:SS` text ([[lsg/Ref/Logseq Published Site/Transclusion]]).
			- **Editing only.** `mod+shift+y` and the `Embed YouTube timestamp` command insert the current player time ([`commands.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/commands.cljs#L669-L680)). Publishing has no editor.

	- ## What lsg publishes
		- The SDK reads the argument of `{{video}}`, `{{youtube}}`, `{{vimeo}}` and `{{bilibili}}` in the order of Logseq's `get-matched-video`: YouTube (`youtube.com`, `youtu.be`, `y2u.be` with an 11-character id) to `https://www.youtube.com/embed/<id>?enablejsapi=1`, `youtube-nocookie.com`, Loom, Vimeo, and Bilibili with `&page=` from `?p=`, to the embed addresses in the table above; any other URL to itself. `{{youtube}}` also accepts an 11-character id. [[lsg/Ref/Rendering and Assets]] describes media for readers.
		- A `{{video}}` URL's start time comes from `t=` in its query or fragment, as seconds with or without `s`, or in `XhYmZs` form: `watch?v=TQsP_PlCY1I&t=205s` starts at 205 and `youtu.be/yxi1O0T4l6k?t=14` at 14. `{{youtube}}` has no start time.
		- Each valid video macro renders, inline in its block's content, `div.lsg-video`: a dark box the full width of the block, `min(315px, (viewport width − 96px) × 315/560)` tall, with a `16px 0` margin and a centred play link. The link's accessible name names the provider, such as `Play YouTube video`, and its `href` is the video's watch address. On the Omer Hamerman page the area is 718px wide and 315px tall at 1280×800, and 165px tall at 390×844, with no sideways scroll.
		- With `media.js`, activating the play link replaces the box with the provider's iframe, adding `autoplay=1` and the start time, with `allowfullscreen`, Logseq's `allow` list `accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope` and a `title` such as `YouTube video`. Without JavaScript, the link opens the video on its site. A URL on another host gets Logseq's plain iframe behind the same box.
		- A non-URL argument renders `span.warning` titled `Invalid URL`, and a missing one `span.warning` titled `Empty URL`, each with the macro text.
		- `{{youtube-timestamp N}}` accepts whole seconds, `M:SS` or `H:MM:SS` with minutes and seconds 0–59, and is bound to the nearest YouTube or `youtube-nocookie.com` video before it in its page's outline, depth first. A bound timestamp renders `a.svg-small.youtube-timestamp` with a 12px clock icon, drawn once by the stylesheet, and the time as `MM:SS`, or `HH:MM:SS` when the hour is not zero. Its `href` is the video's watch address at that time, such as `https://www.youtube.com/watch?v=6cqVzgVQJfE&t=280s`. It uses Logseq's measured colour `rgb(52, 81, 178)` in the light theme and the theme's link colour in the dark theme, with no underline.
		- On the Omer Hamerman page the 13 timestamps read `00:00` … `15:26`, each reachable with Tab. `{{youtube-timestamp 3600}}` reads `01:00:00`. A timestamp with no video before it shows the icon and time as text, and an argument the parser rejects renders nothing and reports a diagnostic.
		- On a plain click of a bound timestamp, `media.js` dispatches a bubbling, cancelable `lsg:media-seek` event with the watch address as `source`, the seconds and the anchor, the same event the dialogue timestamps of audio pages use. If a host cancels it, the script does nothing more. Otherwise the script loads the bound placeholder at that time and plays, or sends `seekTo` and `playVideo` to the loaded player with `postMessage`, without loading YouTube's `iframe_api`, and the page stays put. Clicking `04:40` on the Omer Hamerman page plays from 280 seconds before and after the player has loaded. Modified clicks keep ordinary link behaviour. [[lsg/Ref/Host Integration API]] describes the event.
		- On the AI Engineer Summit workshops page, a timestamp under the second `TQsP_PlCY1I` video seeks the second player and leaves the first unchanged.
		- In block reference, embed and Linked References copies, a timestamp links to its source page's video at its time and is bound to no player on the current page.
		- Search records, block reference text and breadcrumbs show a timestamp as its displayed time: a reference to the heading `{{youtube-timestamp 620}} Agent skill` reads `10:20 Agent skill`.
		- Image syntax for `.mp4`, `.webm` and `.mov` assets or HTTPS URLs renders `div.asset-ref-wrap` with `data-ext` holding `<video src controls preload="none">`, centred.
		- Only pages with a video or a bound timestamp load `media.js` and `media.css`; other pages are unchanged.
		- The SDK's `media` module parses the macros, classifies providers, computes embed and watch addresses and start times, numbers the videos on a page, binds each timestamp, and gives a timestamp's text form. The publisher writes the placeholder, iframe and video markup, the timestamp link, `media.css` and `media.js`.
		- Recorded on 2026-10-28 with the change on the whole encode garden, each page left for 40 seconds in a fresh window: neither the Omer Hamerman page nor the AI Engineer Summit workshops page made a request to a video provider or Google host before a click, on desktop or on the phone profile. The player area measured 728×315 on desktop and 298×178 on the phone profile, and clicking the first timestamp loaded `https://www.youtube.com/embed/6cqVzgVQJfE` with `start=0`. [[lsg/Ref/Logseq Compatibility/Performance]] holds the rows.
	- ## Performance
		- Logseq's eager iframes cost about 1.2 MB and YouTube's player script on every page with a video, whether or not the reader watches it. `lsg` loads nothing from a third-party host until the reader activates a player or a timestamp.
		- The `[media]` table of [`scripts/parity/budgets.toml`](https://github.com/codekiln/logseq-gardener/blob/main/scripts/parity/budgets.toml) holds the budgets: `media.js` at most 3 KB uncompressed, `media.css` at most 1 KB gzip, at most 0.6 KB of markup for each placeholder, growth of at most 20 KB gzip over 73,931 bytes for `Person/Gergely Orosz/Pod/26/09 Design Engineering with Maggie Appleton`, the page with 846 timestamps, and no third-party request before a click. `parity:budgets` checks the sizes in CI and `parity:perf` counts the third-party requests.
		- The `[desktop]` and `[phone]` first-paint budgets apply unchanged to every fixture page. The clock icon is drawn once by the stylesheet, so each timestamp adds only its link and attributes. After a click, the player's heap is YouTube's.
	- ## Differences from Logseq
		- `lsg` shows a placeholder until the reader asks for the player. Logseq loads every player when the page renders, even far below the fold, which costs about 1.2 MB per page from YouTube and Google.
		- The placeholder is a dark box with a play button. A poster image from `i.ytimg.com` would be one request per video that tells YouTube about the visit.
		- `lsg` honours `t=` in the query or fragment and the `1m30s` form, which YouTube honours when the link is opened. Logseq reads only `&t=<digits>`, so 4 garden pages that use `youtu.be/…?t=` start at a different time.
		- A timestamp has an `href` to the video at its time, so it is focusable and works without JavaScript. Logseq's timestamp is an anchor without `href`.
		- A timestamp seeks the nearest video before it in its page's outline. Logseq gives two players of one video the same `id` and seeks the last registered one.
		- A timestamp copied into Linked References or an embed opens its source page's video at its time. Logseq seeks whatever video sits above it on screen.
		- `lsg` seeks with `postMessage` commands and never loads YouTube's `iframe_api`.
		- Video files load with `preload="none"`, as audio does. Logseq's `<video>` uses the browser default, which can download the file before the reader plays it.
		- `{{tweet}}` renders as literal code and `{{twitter}}` as an unsupported-macro warning, each with a diagnostic. Logseq loads Twitter's widget script and draws the tweet.
		- Logseq's dark-theme values were not measured; the styles use `lsg`'s theme tokens.
	- ## Before the change
		- The `lsg` build measured on 2026-10-26, from `48fcc54` on garden commit `083106d`, showed every video and timestamp macro as literal code, so every YouTube note page showed source text where Logseq shows a player. Sources: `crates/logseq-gardener-sdk/src/site/render.rs`, `dialogue.rs`, `dialogue.js`, and the [published-inline-markup](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/published-inline-markup/spec.md), [local-static-publishing](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/local-static-publishing/spec.md) and [published-dialogue-timestamps](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/published-dialogue-timestamps/spec.md) specifications.
		- **Macros were literal code.** `macro_fallback` wrote `video`, `youtube`, `youtube-timestamp` and `tweet` as `<code>{{name args}}</code>` and reported `Unsupported macro (including embeds and queries); preserved as literal text`, for example `{{video https://www.youtube.com/watch?v=6cqVzgVQJfE}}`. `{{vimeo}}` and `{{bilibili}}` were not in that list, so they would have rendered as `span.warning` chips. The build's page bodies held 127 literal `{{video` and 2,786 literal `{{youtube-timestamp` (more in linked reference fragments).
		- **Timestamp headings.** On the Omer Hamerman page each chapter heading read `{{youtube-timestamp 41}} Introducing tuicr`, in code style.
		- **Video files.** `.mp4` and `.webm` assets were copied into the build, but image syntax for them rendered a plain link (`<a href="assets/film.mp4">Film</a>`). Only MP3, WAV and OGG got `<audio controls preload="none">`.
		- **Dialogue seeking.** For pages with exactly one original audio recording, `lsg` turned `speaker · MM:SS — text` lines into `a.dialogue-timestamp` links with `href="<recording>#t=<seconds>"` and `data-lsg-dialogue-time`. `dialogue.js` (2,430 bytes, loaded only by the 3 pages that need it) dispatched a cancelable `lsg:media-seek` event with `{source, seconds, anchor}`; Gitpa's sticky player cancels it and plays the moment itself, and otherwise the script seeks the page's `<audio data-lsg-recording>`. It did not know YouTube, and `{{youtube-timestamp}}` did not produce these links.
		- **Sizes.** The Omer Hamerman page was 43,008 bytes (11,997 gzipped). The largest timestamp page, `Person/Gergely Orosz/Pod/26/09 Design Engineering with Maggie Appleton` (846 timestamps), was 447,528 bytes (73,931 gzipped), within the 100 KB first-paint budget.
