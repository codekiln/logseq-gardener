- # Search Compatibility
	- `lsg` publishes Logseq's search dialog: Cmd/Ctrl+K and the header button open an 896px dialog with the `What are you looking for?` input, results in the Filters, Pages, Commands, Current page and Blocks groups with count badges, five rows per group until `Show more`, block breadcrumbs, highlighted words, `alias of` for alias matches, `/` filters and Logseq's keyboard keys. Page titles match with Logseq's in-order characters rule and fuzzy score, while blocks match when every query word starts a word of the block, so block search has no typo tolerance. The dialog leaves out Create, Files, Whiteboards and Recents, lists only the published site's own commands, and cannot open results in the right sidebar. It loads a small title index and the word shards each query needs, where Logseq searches the whole graph it loads with every page.
	  id:: 3f26eb79-c988-407e-9d2c-1d8023f390de
	- Measured on 2026-10-26 against the `gh-pages` build of garden commit `0ce74d6` (`gh-pages` `8132c95`, served locally, light theme, 1280×800) and an `lsg` build of the same commit from `lsg` `1e72969` with the `parity:build` options plus `--search`. Timings come from `mise run parity:perf --search-site` with [`scripts/parity/search-queries.txt`](https://github.com/codekiln/logseq-gardener/blob/main/scripts/parity/search-queries.txt). The OpenSpec change [match-logseq-search](https://github.com/codekiln/logseq-gardener/tree/main/openspec/changes/archive/2026-10-27-match-logseq-search) then built the grouped dialog and search format version 2, and [accessible-static-search](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/accessible-static-search/spec.md), [garden-search-index](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/garden-search-index/spec.md), [static-search-contract](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/static-search-contract/spec.md) and [static-search-validation](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/static-search-validation/spec.md) hold its requirements.
	- ## What Logseq's published site shows
		- Source links point at the local `logseq/og` checkout, `6e7afa8eb` (`frontend` = `src/main/frontend`; `cmdk.cljs` = `frontend/components/cmdk.cljs`; `list_item` = `deps/shui/src/logseq/shui/list_item/v1.cljs`). Measured live values come first and win where they differ from the checkout or from [[lsg/Ref/Logseq Published Site/Search and More Menu]] and [[lsg/Ref/Logseq Published Site/Clickable Prototype]]. The board's 720px white dialog, bold matches and `PAGES`/`BLOCKS` labels do not match the live build.
		- None of the search code checks whether the site is published, so the published dialog is the desktop app's dialog, including commands and page creation.
		- ### Opening
			- The header search button, `mod+k`, `mod+shift+p` (commands only) and `mod+shift+k` (current page only) open it ([`shortcut/config.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/modules/shortcut/config.cljs#L364-L369), [`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L897-L901)). Other shortcuts are off while it is open.
			- A modal 896px wide (`90dvw`, max `56rem`), 8px radius, with no title and no close button ([`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L966)).
			- The input: 20px, transparent, no border, placeholder `What are you looking for?`, on a grey row with a bottom border ([`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L733-L753)).
			- The results area is 65% of the viewport height and scrolls. A footer shows one tip (`Type / to filter search results`, `⌘ ⏎ to open search in the sidebar`) and the keys for the highlighted row (`Open ⏎`, `Open in sidebar ⇧ ⏎`).
		- ### Groups
			- Order: Filters (when the input contains `/`), Pages, Create, Commands, Current page, Blocks, Files, Recents. Empty groups are left out ([`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L105-L144)).
			- Each group header is 32px, 12px grey text with a bold name, then a count badge that reads `99+` at 100 or more ([`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L574-L604)).
			- **Empty input:** Commands (70 in the published build, starting `Toggle wide mode`, `Toggle between dark/light theme`, `Toggle settings`) and Recents. Recents reads recently opened pages from Logseq's in-memory database ([`handler/recent.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/handler/recent.cljs#L6-L18)); after opening `mise` in the same session, the measured dialog still showed only Commands.
			- **Query `tmux`:** Pages `99+` (`tmux`, `tmux/Option/pane-border-style`, `tmux.conf.local` with `alias of tmux/Config/local`, `tmux/Window/Name`, `tmux/session/Picker/Order`), then Blocks `99+`, each row a breadcrumb of the page and up to three parents above the block text. Blocks on the page being viewed move to a Current page group ([`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L298-L311)).
			- **Query `logseq query`:** no Pages group, a Create group (`Create page`, `Create whiteboard`), and Blocks `99+` starting with `Logseq/MCP/Server/Survey/Report`. Create appears whenever no page has exactly the typed name ([`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L103-L104)); in the published build it creates a page only in the reader's memory.
		- ### Five rows and Show more
			- Each group shows 5 rows unless it is expanded, a filter is set, or the search is in the right sidebar ([`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L43), [L92–L102](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L92-L102)).
			- The group that holds the highlighted row shows `Show more ⌘ ↓` (or `Show less ⌘ ↑`) in its header; `mod+Down` and `mod+Up` do the same, and clicking the group name toggles it ([`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L592-L604), [L697–L702](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L697-L702)).
		- ### `/` filters
			- Typing `/` shows a Filters group with six rows, each `Search only <kind> — Add filter to search`: pages, current page, blocks, commands, whiteboards, files ([`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L45-L57)). Text after the `/` narrows them by fuzzy match. Pages and Blocks that match `/` follow, so a bare `/` also lists blocks containing a slash.
			- Choosing a filter removes the `/…` text and shows a `Search only: <kind>` chip with `×`. Escape on an empty input or Backspace on an empty input removes it ([`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L515-L532), [L764–L776](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L764-L776)).
			- With a filter set, the group shows all its rows. The blocks filter also shows Current page.
		- ### Matching
			- **Pages:** a fuzzy match (Fuse, threshold 0.5) on the page name with brackets, slashes, underscores, parentheses and spaces removed, at most 100 results, then kept only when the query's characters appear in order in the name ([`search.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/search.cljs#L41-L43), [L121–L157](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/search.cljs#L121-L157), [`search/db.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/search/db.cljs#L101-L120)). Aliases show `alias of <page>`.
			- **Blocks:** a fuzzy match (Fuse, threshold 0.35) on the raw block text including property lines, at most 100 results ([`search/db.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/search/db.cljs#L82-L93), [`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L280)).
			- **Highlight:** each whitespace-separated query word is marked case-insensitively in the row text and its breadcrumb, as `span.ui__list-item-highlighted-span` on `rgb(198,212,249)`, 14px weight 500 ([`list_item`](https://github.com/logseq/og/blob/6e7afa8eb/deps/shui/src/logseq/shui/list_item/v1.cljs#L18-L41)).
			- Rows are 14px weight 500 with a 20×20 icon box; the highlighted row has a grey background ([`list_item`](https://github.com/logseq/og/blob/6e7afa8eb/deps/shui/src/logseq/shui/list_item/v1.cljs#L57-L92)).
			- Input changes are handled at most every 50 ms ([`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L664-L670)).
		- ### Keyboard
			- Down or Ctrl+N, Up or Ctrl+P move through all visible rows across groups and wrap ([`cmdk.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/cmdk.cljs#L642-L716)).
			- Enter opens a page, opens a block at `#ls-block-<uuid>` on its page (or zooms into it when a parent is collapsed), runs a command or applies a filter.
			- Shift+Enter opens the page or block in the right sidebar; Mod+Enter adds the whole search to the right sidebar; Mod+C copies a block reference.
			- Escape clears the input, then the filter, then closes. There is no Tab movement between groups.
		- ### Performance in Logseq
			- Search runs against the whole graph, which the published site loads before any page draws (22.6 MB transferred, about 2 GB peak heap; [[lsg/Ref/Logseq Compatibility/Performance]]). Both fuzzy indexes are built on the first search.
			- Measured on 2026-10-26:
				- | Profile | Median per key (ms) | 95th percentile (ms) |
				  | --- | ---: | ---: |
				  | desktop | 776 | 1,836 |
				  | phone | 2,950 | 13,675 |
	- ## What lsg publishes
		- Publishing with `--search` adds a search button to the header; the button and Cmd/Ctrl+K open the dialog. A 2 KB starter loads with the page, and the dialog module, the engine, the manifest and the title index load when a reader points at or focuses the search button, presses Cmd/Ctrl+K or opens search. [[lsg/Ref/Search Dialog]] describes the dialog for readers and hosts, and [[lsg/Ref/Static Search Data]] describes the files.
		- The dialog follows Logseq's published layout: at most 896px wide (90% of the viewport below that), 8px radius, no visible title or close button, a 20px borderless input with the placeholder `What are you looking for?` on a grey row with a bottom border, results filling at most 65% of the viewport height, and a footer with one tip and the keys for the highlighted row. The dialog keeps `aria-label="Search"` and a visually hidden input label, and closes on Escape or a click outside it.
		- Results appear in the groups Filters, Pages, Commands, Current page and Blocks, in that order, leaving out empty groups. Each group header shows the group name and its full match count, shown as `99+` from 100. Blocks on the page being viewed appear under Current page and not under Blocks. Searching `tmux` on the home page gives a Pages group with `99+` before a Blocks group with `99+`.
		- Each group shows five rows until it is expanded or a filter is set. The group holding the highlighted row shows `Show more ⌘ ↓` or `Show less ⌘ ↑` (`Ctrl` in place of `⌘` off Apple systems); `mod+Down`, `mod+Up` and a click on the group name expand or collapse it. Each group returns at most 100 results.
		- Page rows show the title and, for an alias match, `alias of <page>`: `tmux.conf.local` shows `alias of tmux/Config/local`. Block rows show a breadcrumb of the page title and up to three parents above the block text. Each query word is highlighted case-insensitively in titles, block text and breadcrumbs as `span.ui__list-item-highlighted-span`, on Logseq's `rgb(198,212,249)` in the light theme and a theme token in the dark theme.
		- Pages match when the query's characters, ignoring spaces, brackets, slashes, underscores and parentheses, appear in order in the title or an alias. They rank as exact title, exact alias, title or alias prefix, then by Logseq's fuzzy page `score`, ties in title order.
		- Blocks match when every query word starts a word of the block's text. They rank by how many query words equal a whole word, ties in record order. A one-character query word matches only that whole word, and a query of one-character words searches titles alone.
		- Typing `/` lists the filters `Search only pages`, `current page`, `blocks` and `commands`. A filter shows its group in full; Escape on an empty input or Backspace removes it.
		- The Commands group lists the published site's actions: toggle the theme, toggle the left sidebar, toggle wide mode, and go to the home page, All pages and journals when the site has them. Commands show on an empty input and when their names match the query, and Enter runs the highlighted one.
		- Up and Ctrl+P, Down and Ctrl+N move the highlight through every visible row across groups and wrap at the ends. Enter opens the highlighted page or block, runs a command or applies a filter. Escape clears the input, then removes the filter, then closes the dialog.
		- Search format version 2 writes a title index, word shards keyed by the first two characters of a word and split while one exceeds 64 KB gzip, and record chunks of up to 256 block records and at most 32 KB gzip, each named by a content digest. Each keystroke fetches the shards its words need, then only the chunks of the rows it draws; a row whose chunk is still loading shows its page title and a placeholder line.
		- Search indexes page titles, unique aliases and bullet text. It leaves out property values, code fences, tables, generated namespace titles and the text of embedded blocks.
		- The SDK builds the records, the word index, the shards and chunks, and answers the same query in Rust as the browser engine does; `tests/search-fixture.json` runs in both. The publisher writes the files and draws the dialog from `search-ui.mjs` and its styles.
		- On the whole encode garden, measured on 2026-10-27, every `lsg` value of search format version 2 is within its budget: the dialog showed 23 ms after Cmd/Ctrl+K on desktop and 245 ms on the phone profile, and page results 110 ms and 2,378 ms after it. [[lsg/Ref/Logseq Compatibility/Search Performance]] holds every measure and the budgets in the `[search]` table of [`scripts/parity/budgets.toml`](https://github.com/codekiln/logseq-gardener/blob/main/scripts/parity/budgets.toml), and `mise run parity:build` passes `--search`, so [[lsg/Ref/Logseq Compatibility/Performance]] records search for both builds.
	- ## Differences from Logseq
		- Blocks match by word prefix, so block search has no typo tolerance. Logseq's Fuse match finds blocks with typos, but fuzzy block matching would need every block's text in the browser. Page titles keep fuzzy matching, which covers a misspelt page name.
		- Search loads a small title index and the shards each query needs. Logseq searches the whole graph, which its published site loads before any page draws.
		- The Create group is left out. Logseq's published `Create page` makes a page only in the reader's memory, which disappears on reload.
		- The Commands group lists only the published site's own actions. Logseq lists 70 commands, most of which edit the graph.
		- Recents is left out. The live published build showed no Recents group after opening pages in the same session, and keeping a history would need storage on the reader's device.
		- The whiteboards and files filters and the Files and Whiteboards groups are left out, since `lsg` publishes neither.
		- Search results and the whole search do not open in the right sidebar: Shift+Enter and Mod+Enter do nothing, and Mod+C does not copy a block reference.
		- `mod+shift+p` and `mod+shift+k` do not open the dialog.
		- Logseq's dark-theme values were not measured; the dialog uses `lsg`'s theme tokens in the dark theme.
	- ## Before the change
		- The `lsg` build measured on 2026-10-26, from `1e72969`, had the search of [issue 94](https://github.com/codekiln/logseq-gardener/issues/94) to [issue 96](https://github.com/codekiln/logseq-gardener/issues/96): one ungrouped list of at most 20 results with no highlighting, no filters and no sidebar. These facts come from `crates/logseq-gardener-sdk/src/site/search.rs`, `search-ui.mjs`, `search.mjs` and the static search contract of the time, checked against the whole-garden build.
		- **Opening:** a header button and Cmd/Ctrl+K opened a native `<dialog>` titled `Search garden` with a `Close` button and a visible label `Search published pages and notes`. The dialog was 680px wide with 20px padding and a 10px radius; the input was 16px with a border and no placeholder. Empty input showed `Type to search published pages and notes.`
		- **Results:** one list of at most 20 results with a live status line (`20 results shown.`). Page results showed the title; content results showed the page title, the breadcrumb joined with `›`, and a bounded snippet. Ranking put exact titles, exact aliases, prefixes and all-term title matches before content matches; ties sorted by title. For `tmux` the list was 20 `tmux…` titles in alphabetical order and no content result.
		- **Matching:** every query word had to appear as a literal substring of one title, alias or bullet. There was no fuzzy match, so typos found nothing.
		- **Missing:** groups, the five-row limit with `Show more`, the count badges, highlighting, `alias of`, the Current page group, `/` filters (`/` matched titles containing a slash: `10/3/3`, `12factor/app`), Recents, commands, the footer hints, Shift+Enter and Mod+Enter.
		- **Not indexed:** property values, generated namespace titles and code fences.
		- **Size:** the search corpus was one 32.2 MB JSON file (5.6 MB gzipped) with 101,671 records. The first search on the phone profile took 29.4 s and grew the heap by 75 MB, over the budgets of the time (8 MB decoded, 1 MB gzipped, 10 s, 30 MB). The earlier static search validation measured only 996 pages, and the parity build did not pass `--search`, so this had not been visible.
		- **Size and speed on the whole garden** (`parity:perf --search-site`). Bold values exceeded the `[search]` budgets; the corpus also exceeded `corpus_decoded_mb = 8` and `corpus_gzip_kb = 1000`. Page first paint was unaffected: 12 KB data and 9.7 KB script before the title.
			- | Profile | First open (ms) | Transferred (MB) | Decoded (MB) | Heap growth (MB) | Warm open (ms) | Median per key (ms) | 95th percentile (ms) |
			  | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
			  | desktop | 845 | 5.63 | 32.3 | **47.1** | 13 | 8.8 | 36.9 |
			  | phone | **29,449** | 5.63 | 32.3 | **74.7** | 30 | 39.7 | 85.1 |
		- Once its corpus had loaded, `lsg` already typed faster than Logseq: 8.8 ms median and 36.9 ms 95th percentile on desktop, 39.7 ms and 85.1 ms on phone, against Logseq's 776 ms and 1,836 ms on desktop and 2,950 ms and 13,675 ms on phone.
		- **The parity build:** `mise run parity:build` did not pass `--search`, so the committed `parity:perf` rows for `lsg` search timed out instead of measuring.
		- **Where the code lived:** the corpus was built inside the publisher's `site` module from each rendered page; the CLI and the language server could not query it.
