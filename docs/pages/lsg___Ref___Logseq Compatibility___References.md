- # References Compatibility
	- `lsg` publishes the sections below a page's outline in Logseq's order, Pages tagged with, Linked References, Hierarchy and Unlinked References, with Logseq's count of referring blocks, which includes references to namespace children, groups with journals newest first, breadcrumbs of up to three ancestors, the filter dialog with include and exclude chips, and the page's `filters::` property as the starting filter. It orders the groups of pages other than journals by title, where Logseq uses database order, leaves property names out of the filter chips, links each breadcrumb crumb to the ancestor's place on its page, keeps a reader's filter for the visit, and loads each section's groups from separate files when the reader opens the section.
	  id:: f3267246-cff6-4b3e-b38d-22175e0ca07b
	- Measured on 2026-10-25 against the `gh-pages` build of garden commit `c622a4d` (served locally, light theme, 1280×800) and an `lsg` build of the whole garden at commit `0ce74d6` from `lsg` `3f8e7c2` (`mise run parity:build`). The OpenSpec change [match-logseq-references](https://github.com/codekiln/logseq-gardener/tree/main/openspec/changes/archive/2026-10-26-match-logseq-references) then built the sections, and [published-reference-sections](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/published-reference-sections/spec.md), [published-linked-references](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/published-linked-references/spec.md), [published-unlinked-references](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/published-unlinked-references/spec.md), [published-tagged-pages](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/published-tagged-pages/spec.md) and [reference-index](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/reference-index/spec.md) hold their requirements.
	- ## What Logseq's published site shows
		- Below each page's outline, Logseq shows up to four sections in this order: Pages tagged with, Linked References, Hierarchy, Unlinked References. Linked References counts referring blocks, includes blocks that refer to any page in the target's namespace, groups them by page with journals newest first, and puts a filter icon in the header that opens a dialog of include and exclude chips. Unlinked References lists blocks that mention the page name as plain text, and Logseq searches for them only when a reader opens the section. On the encode garden, Logseq reports 589 linked references for `mise`.
		- Source links point at the local `logseq/og` checkout, `6e7afa8eb` (`frontend` = `src/main/frontend`). Measured live values come first and win where they differ from the checkout or from [[lsg/Ref/Logseq Published Site/Backlinks]]; the board's group colours, breadcrumb size and chip colours differ from the live build.
		- ### Section order and visibility
			- [`page.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/page.cljs#L507-L524) renders, after the outline:
				- **Pages tagged with**, on every page that is not a zoomed block, when at least one page has this page in `tags::`.
				- **Linked References**, on every page that is not a zoomed block. The section is left out entirely when no block refers to the page and no filter is set ([`reference.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/reference.cljs#L241-L245)). On `Microfreak/UG/07 Filter/Asset/01-The-Analogue-Filter` the page shows only Hierarchy and Unlinked References.
				- **Hierarchy**, on pages that are not journals.
				- **Unlinked References**, on every page outside the right sidebar, always shown with its header.
			- Each section header is a foldable row: a 14px chevron at `margin-left: -30px`, then the `h2`. The Linked References section sits in `.content.pt-6` (24px top padding); Pages tagged with and Unlinked References have a 24px top margin.
		- ### What counts as a linked reference
			- Logseq queries every block whose `:block/path-refs` include the page or one of its aliases ([`model.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/db/model.cljs#L1255-L1281)), then counts the blocks whose own `:block/refs` include it ([`reference.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/reference.cljs#L208-L215)). Blocks on the page itself are left out.
			- **Namespace parents count.** When a block refers to `[[mise/Config]]`, the parser adds `mise` to the block's references as well ([`graph_parser/block.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/deps/graph-parser/src/logseq/graph_parser/block.cljs#L358-L367)). So `mise` lists every block that refers to any `mise/…` page. This was the main reason `mise` had 589 linked references in Logseq and 151 referring contexts in `lsg` before the change.
			- Page properties count: a page whose `tags::` name the target appears as a group whose block is the page's property block (on `mise`, `Goose/How To/Use Mise to Set AWS Bedrock Env Vars for Desktop App` shows its `cgpt-link::` and `tags::` rows). Property names are also references in Logseq's file graphs, so names such as `card-last-interval` appear as filter options.
		- ### Count text
			- `N Linked References`, or `1 Linked Reference`; with any filter set, `F of N Linked References` ([`dicts/en.edn`](https://github.com/logseq/og/blob/6e7afa8eb/src/resources/dicts/en.edn#L229-L237)). N counts referring blocks, before filters. There is no page count.
			- Live: `h2.font-medium`, 16px, weight 500, `rgb(17,24,28)`, 25.6px row.
			- Measured counts: `mise` reads `4 of 589 Linked References` on load (see Filter icon and dialog below), `tmux` 795, `Claude/Code` 657, `Term` 193.
		- ### Collapse
			- The section starts collapsed when N reaches `:ref/linked-references-collapsed-threshold` ([`reference.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/reference.cljs#L131-L133)). The encode garden sets it to 0, so every Linked References section starts collapsed and shows only its header.
			- Each page group is foldable on its own and starts open.
			- Groups render lazily as they scroll into view (`ui/lazy-visible`), and nothing inside the section is drawn until it is opened.
		- ### Groups
			- ```html
			  <div class="flex flex-col references-blocks-wrap">
			    <div class="my-2 references-blocks-item">
			      <div class="foldable-title">…chevron… <a class="page-ref" data-ref="2026-10-19 mon">2026-10-19 Mon</a></div>
			      <div class="breadcrumb block-parents my-2">…</div>
			      <div class="blocks-container">…the referring block and its children…</div>
			    </div>
			  </div>
			  ```
			- One group per referring page ([`block.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/block.cljs#L3521-L3547)). When the page is an alias of the target, a muted `Alias` label follows its title.
			- **Order:** journals first, newest first, then the other pages in database order ([`block.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/block.cljs#L3523)). On `mise` the first groups are `2026-10-19 Mon`, `2026-10-04 Sun`, `2026-09-10 Thu`; the last are `mise/use` and `mise/Tool/Core`. Within a group, blocks whose parent is the page come first.
			- **Style, live:** background `rgb(241,243,245)`, 4px radius, 16px padding, `8px 0` margin, no border. The page title is a plain page link: 16px, weight 400, `rgb(16,107,163)`, no brackets.
			- Each referring block renders with bullets and its children, as in the page outline.
			- `mise` has 222 groups; `tmux` 258.
		- ### Breadcrumbs
			- A referring block that is not top-level gets a breadcrumb of up to 3 ancestors; when there are more, the oldest are replaced by `⋯` ([`block.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/block.cljs#L2564-L2610)). The page is not part of the breadcrumb.
			- Each crumb is the ancestor's first line with its inline markup, so page references keep their grey brackets: on `mise`, `[[Updated]] › mise tasks`.
			- Crumbs are separated by a 20px `chevron-right` icon at 50% opacity with 4px side margins.
			- **Style, live:** 16px body text `rgb(17,24,28)`, margin `8px 0 8px 24px`. The board's 14px muted crumbs do not match the live build.
			- Clicking a crumb opens that ancestor as a zoomed block, `#/page/<uuid>` ([`block.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/block.cljs#L2528-L2557)).
		- ### Filter icon and dialog
			- The header carries `a.filter` with title `Filter`: a funnel icon (`ti-filter`, 16px measured) at 60% opacity with no filter, `text-success` (`rgb(41,151,100)`) when every filter is an include, `text-error` when every filter is an exclude, `text-warning` when mixed ([`reference.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/reference.cljs#L137-L157)). The red and orange values were not measured.
			- Clicking it opens a centred modal, `.ls-filters` (704px wide inside a 768px panel, panel background `rgb(236,238,240)`, 6px radius) ([`reference.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/reference.cljs#L43-L90), [`reference.css`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/reference.css#L1-L20)):
				- A round grey funnel badge, the title `Filter` (18px, weight 500) and the hint `Click to include and shift-click to exclude. Click again to remove.` (12px).
				- `Includes:` and `Excludes:` rows listing the active filters as chips.
				- A search row (search icon, input with placeholder `Search in linked pages`, 16px, background `rgb(251,252,253)`, 4px radius). Typing narrows the chips by fuzzy match.
				- Chips for every other page referenced by the shown blocks, their ancestors or their children, with a superscript count, most frequent first. Chips are outline buttons: 24px tall, 12px text, weight 500, `0 12px` padding, 4px radius, white background, `1px solid rgb(226,232,240)` border. Include and exclude chips look the same as the others; the colour shows only on the header icon.
			- **Options follow the filter.** The chip list and counts come from the filtered blocks ([`reference.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/reference.cljs#L219-L240)). On `mise`, with `Diataxis/How To` included, the dialog shows 21 chips (`Diataxis 4`, `AWS 2`, …); after removing the include it shows 808 (`mise/Config 106`, `mise/Config/mise.toml 74`, `Gard 66`, …). The options include the referring pages themselves and property names.
			- **Matching:** a block stays when its path references include every included page and none of the excluded pages; its ancestors are kept for context ([`handler/block.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/handler/block.cljs#L253-L283)).
			- **Initial filters come from the page.** Logseq reads the page's `filters::` property as the starting filter ([`handler/page.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/handler/page.cljs#L748-L758)). Six garden pages carry one; `mise` has `filters:: {"diataxis/how to" true}`, so its header reads `4 of 589 Linked References` with a green icon before the reader does anything. Changes in the published build last for the session; Logseq's write-back to the file does nothing there.
		- ### Unlinked references
			- The header reads `Unlinked References` and the section starts collapsed ([`reference.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/reference.cljs#L280-L292)). Opening it runs the search; the header then reads `N Unlinked References` (`1 Unlinked Reference`), where N counts blocks.
			- **Search:** a case-insensitive match of the page name and each alias against the text of every block in the graph, with the logbook removed ([`model.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/db/model.cljs#L1320-L1347)). The name must not be preceded by a letter, digit, `#` or `[[`, and must not be followed by a letter or digit. Blocks on the page itself are left out. Blocks that also link the page are not left out, and the name can match inside another page's link text: on `tmux` the first result is `[[My/AI/Rule/Dev/Workflow/Git Worktree PR/Tmux]]`.
			- Results use the same groups as linked references, without breadcrumbs and without filters.
			- Measured: `mise` 2,720 unlinked references on 1,029 pages; `tmux` 856 on 250 pages.
		- ### Pages tagged with
			- Heading `Pages tagged with "<name>"`, where the name is the lower-cased page name (`Pages tagged with "claude/code"`) ([`page.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/page.cljs#L228-L240)). The board shows the original case; the live build lower-cases it.
			- The list holds every page whose `tags::` include this page, sorted by lower-cased name ([`model.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/db/model.cljs#L78-L89)). Each row is a page link with no brackets.
			- Foldable, open by default.
			- **Style, live:** heading 16px, weight 700, opacity 0.5; list margin `8px 0 0 19.2px` with `circle` markers; rows 16px with `4px 0` margins; links `rgb(16,107,163)`.
			- Measured: `Term` 178 pages, `Claude/Code` 38, `mise` 9, `tmux` 2.
		- ### Performance in Logseq
			- Logseq's build downloads the whole graph (`static/js/db.gz`, 19.8 MB) before it draws any page. Every reference, filter and unlinked search then runs in the browser against that database, and the unlinked search scans every block's text each time a reader opens the section.
	- ## What lsg publishes
		- Below the outline, each page shows the sections that apply in Logseq's order: Pages tagged with, Linked References, Hierarchy and Unlinked References. Each section header is a foldable row with a 14px chevron and the heading. Journal pages have no Hierarchy section. [[lsg/Ref/Published Pages]] describes the sections for readers.
		- **What counts:** page links, tags, embed page targets and page-reference property values in selected visible pages, through titles and aliases, once per referring block. A reference to `A/B/C` also counts for `A/B` and `A`, even when `A/B/C` has no page, as Logseq's parser does; an alias reference expands only the name the author wrote. Blocks on the page itself are left out. With these rules `mise`, `tmux` and `McKinsey` match Logseq's block and group counts.
		- **Count text:** `N Linked References`, `1 Linked Reference`, or `F of N Linked References` while a filter is active, counting blocks, at 16px and weight 500. A page with no linked references has no Linked References section.
		- **Collapse:** `:ref/linked-references-collapsed-threshold` (default 100) and `:ref/default-open-blocks-level` (default 2) from `logseq/config.edn` decide which sections and copied parents start closed, so every Linked References section of the encode garden, which sets the threshold to 0, starts closed. Each group folds on its own and starts open.
		- **Groups:** one foldable card per referring page, journals first, newest first, then other pages by lower-cased title; within a group, blocks whose parent is the page come first, then document order. Each card has the surface background, 4px radius, 16px padding and `8px 0` margin, a plain page link at 16px and weight 400 without brackets, and a muted `Alias` label when the page is an alias of the target. Referring blocks render with bullets and their children, as in the page outline, and a bullet opens the block on its source page.
		- **Breadcrumbs:** a referring block below the top level shows its nearest three ancestors, with `⋯` for older ones, each through the inline renderer and linked to the ancestor's anchor on its page, separated by chevrons at 50% opacity, at 16px with `8px 0 8px 24px` margin. `mise` shows the crumb `[[Updated]] › mise tasks`.
		- **Filter:** the funnel in the Linked References header has Logseq's four states and opens a dialog with the title `Filter`, Logseq's hint, `Includes:` and `Excludes:` rows, a `Search in linked pages` input and frequency-sorted chips with superscript counts. Click or Enter includes a chip, shift-click or Shift+Enter excludes it, and activating it again removes it; each chip's accessible name states its state. Chips and counts follow the blocks the current filter keeps. A block matches when its path references include every included page and none of the excluded ones. On `mise` the unfiltered dialog lists `mise/Config` with 103 and `Gard` with 66.
		- **Starting filter:** a page's `filters::` property sets the starting filter, already shown in the first-paint heading and icon colour, so `mise` opens at `4 of 589 Linked References`. A reader's changes last for the visit through `sessionStorage`, scoped to the site and the page.
		- **Unlinked References:** every page ends with a collapsed `Unlinked References` section. Opening it loads the page's mentions and changes the heading to `N Unlinked References`, using Logseq's match rule with logbooks ignored and names inside code counted; results use the linked-reference groups without breadcrumbs or filters. `tmux` shows 856.
		- **Pages tagged with:** a page that published pages tag shows `Pages tagged with "<name>"` with the lower-cased name, the tagging pages sorted by lower-cased title, open by default, with Logseq's measured styles. `Term` lists 178 pages starting with `1Password/Dev/CLI/Secret Reference`.
		- **Loading:** a page's HTML holds each section's header and counts and no groups. The groups sit in fragment files in `_refs/`, about 50 groups per file, and opening a section fetches the first file and the rest as the reader nears the end. Without scripts, each section links its first fragment, a readable page that links the next. `lsg-references.js` loads after the page's `load` event; a host that swaps page content calls `window.logseqGardenerInitReferences(root)`, which [[lsg/Ref/Host Integration API]] describes.
		- Shift-click on a group's bullet adds a card for that block on its source page to the right sidebar, and Shift-click on a crumb adds a Block references card for its block, as in Logseq; [[lsg/Ref/Logseq Compatibility/Right Sidebar]] compares the sidebar.
		- The SDK's `ReferenceIndex` answers every relationship for the publisher, the CLI and the language server: linked blocks, path references for filtering, related pages with counts, the starting filter, tagged pages and unlinked mentions. Unlinked mentions come from one pass over all block text with an Aho–Corasick matcher over every title and alias. The publisher renders the sections, writes the fragment files, and renders each listed block and breadcrumb once per build.
	- ## Performance
		- The `[references]` table of [`scripts/parity/budgets.toml`](https://github.com/codekiln/logseq-gardener/blob/main/scripts/parity/budgets.toml) holds the budgets: the references script at most 7 KB, the references styles at most 1 KB gzip on every page, each fragment file at most 100 KB gzip, the first group within 300 ms on desktop and 1,500 ms on the phone profile after opening a section, a peak phone heap of at most 20 MB after opening both sections on `mise` and scrolling to the end, a filter change on `mise` within 50 ms on desktop, and a whole-garden build at most 25% slower than the build before the change. `Answer/AI`, `note/my`, `mise` and `Claude/Code` each send at most 100 KB before their title, with no reference group in their HTML.
		- `parity:budgets` checks the sizes in CI, and `parity:perf` marks the others. [[lsg/Ref/Logseq Compatibility/Performance]] recorded, with `lsg` `84e9278`, opening Linked References on `mise` in 22 ms on desktop and 346 ms on the phone profile, a filter change in 46 ms on desktop, opening Unlinked References in 12 ms and 243 ms, 449 groups loaded, and a peak heap of 4.1 MB on desktop and 3.4 MB on the phone profile.
	- ## Differences from Logseq
		- Groups of pages other than journals sort by lower-cased title. Logseq uses database insertion order, which a build cannot reproduce.
		- Property names are not references and give no filter chip. Logseq's file graphs turn names such as `card-last-interval` into pages; they have no published page, so a chip for them would lead nowhere. Page-reference property values still count.
		- A breadcrumb crumb links to the ancestor's anchor on its page, where block zoom can show it. Logseq opens `#/page/<uuid>` through its client-side router.
		- A reader's filter changes last for the visit through `sessionStorage`. Logseq keeps them in memory for the session.
		- Section groups load from fragment files when a section opens. Logseq renders them in the browser from the whole graph.
		- Filter chip counts follow Logseq's counting, with small differences on some pages: on `mise`, `mise/Config` counts 103 against Logseq's 106.
		- A zoomed block shows no references below it, and referenced blocks show no reference count beside them.
		- Logseq's dark-theme values were not measured; the sections use `lsg`'s theme tokens.
	- ## Before the change
		- The `lsg` build measured on 2026-10-25, from `3f8e7c2`, built linked references from `crates/logseq-gardener-sdk/src/site/backlinks.rs`, `backlinks.js` and the page styles in `site/mod.rs`, following the published linked references spec of that time.
		- **What counted:** page links, tags, embed targets and page-reference property values, through selected titles and aliases, deduplicated per referring block. References to namespace children (`[[mise/Config]]` for `mise`) did not count, so `mise` reported 151 referring contexts against Logseq's 589.
		- **Count text:** `Linked references — 111 pages · 151 referring contexts` on `mise`, with an explanation of contexts inside the section. The page count led; equal totals showed only pages.
		- **Zero references:** a heading reading `0 pages`; 3,529 pages in the build showed one.
		- **Collapse:** a native `<details>` that honoured the collapse threshold and the open depth, so every section in the encode garden started closed.
		- **Section order:** Hierarchy came before Linked references.
		- **Groups:** one `section.backlinks-group` per page on `--lsg-surface` (`rgb(241,243,245)`), 5.6px radius, `12px 16px` padding, `16px 0` margin, with a bold `h3` link. Groups sorted alphabetically by title, so journals came in date order oldest first and mixed with other pages.
		- **Breadcrumbs:** `p.backlink-context`, 13.6px, every ancestor as plain text separated by `›`, then a `↗` link to the referring block. There was no level limit: one `mise` breadcrumb had eight crumbs.
		- **Filters:** an inline fieldset `Related pages` with a search box and one `Any / Include / Exclude` select per related page (329 on `mise`), a reset button and a live status line. Options were fixed at build time and did not follow the active filter. `filters::` was hidden from the properties and not applied.
		- **Missing:** Pages tagged with and Unlinked References.
		- **Size:** the reference section was inlined in each page and its script in every page. It was 449 KB of `mise`'s 511 KB, and 99% of `Answer/AI` (2.2 MB, 372 KB gzipped) and `note/my` (2.1 MB).
		- **Where the code lived:** the reference index (`Backlinks::new`) was built inside the publisher's `site` module; no SDK operation answered what refers to a page.
