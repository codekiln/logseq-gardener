LOGSEQ-ENCODE-GARDEN · STATIC SITE

How the published garden is built and drawn

The site is the Logseq web app compiled in publishing mode: the whole graph ships as data inside one page, and the app renders it read-only on GitHub Pages.

1 · How it ships .github/workflows/gh-pages.yml, on every push to main

STEP 1
Guard the sentinel
Fails the build if pages/ or journals/ contain a literal logseq____&amp;-style token, which would corrupt the embedded JSON and blank the site.
STEP 2
logseq/publish-spa
Builds the app from graph . into www/ with accent color indigo. All pages are public: :publishing/all-pages-public? true.
STEP 3
Add .nojekyll
Stops GitHub Pages from running Jekyll over the build, so paths with underscores are served as-is.
STEP 4
Compress the graph
compress_logseq_db.py moves the inline window.logseq_db into static/js/db.gz and swaps in a loader, keeping index.html under GitHub's 100 MB limit.
STEP 5
Deploy to gh-pages
Pushes www/ to the gh-pages branch with a clean deploy. To preview locally, extract that branch and serve it over http on localhost.
