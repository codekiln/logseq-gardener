- # Journals Compatibility
	- `lsg` publishes Logseq's journals: each journal file as a page titled with `:journal/page-title-format`, links to journals in Logseq's accepted date formats, and a journals feed on the home page, newest first, three journals at a time and seven more as the reader nears the bottom, each with its blocks and a collapsed Linked References section, with Journals first in the left sidebar and the `g j` shortcut. It publishes journals only when the build asks for them with `--journals`, its feed lists the journals dated on or before the build date where Logseq uses the reader's date, it leaves out today's default queries and the scheduled and deadline section, and it publishes no page for a date that only links mention.
	  id:: 1dc6ead6-a039-4ea4-aa89-709ac81415ed
	- Measured on 2026-10-25 against the `gh-pages` build of garden commit `09cf7fb` (506 journal files; served locally) and an `lsg` build of the whole garden from `ac32058` (`mise run parity:build`, then `parity:compare`). The OpenSpec change [publish-logseq-journals](https://github.com/codekiln/logseq-gardener/tree/main/openspec/changes/archive/2026-10-25-publish-logseq-journals) then published journals and the feed, and [journal-weekday-token](https://github.com/codekiln/logseq-gardener/tree/main/openspec/changes/archive/2026-10-31-journal-weekday-token) added the `E` token. [published-journals](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/published-journals/spec.md) and [journal-identity](https://github.com/codekiln/logseq-gardener/blob/main/openspec/specs/journal-identity/spec.md) hold their requirements.
	- ## What Logseq's published site shows
		- The local `logseq/og` checkout is `1.0.0-12-g6e7afa8eb`, the file-graph continuation of 0.10; its journal code matches 0.10's structure. Links below point at that commit (`frontend` = `src/main/frontend`). The live build agrees with the source except where noted.
		- ### Configuration in the encode garden
			- From `logseq/config.edn`:
				- `:journal/page-title-format "yyyy-MM-dd EEE"`.
				- `:default-home` is unset, so the home route shows journals.
				- `:feature/enable-journals?` is unset, which means enabled.
				- `:ref/linked-references-collapsed-threshold 0`, so every Linked References section starts collapsed.
				- `:default-queries {:journals [NOW, NEXT]}`, shown only on today's journal.
		- ### The home route
			- [`components/container.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/container.cljs#L710-L747) `main-content` decides what `#/` shows, in this order:
				- If `:default-home` names an existing page, `#/` redirects to it.
				- On a published site with no default home and no journals, `#/` redirects to All pages.
				- Otherwise `#/` renders the journals feed.
		- ### The journals feed
			- [`components/journal.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/journal.cljs#L26-L87) and [`db/model.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/db/model.cljs#L1090-L1111) build the feed.
			- **Which journals:** every page with a journal date on or before today, newest first. Future dates are left out. Nothing filters on content, so a date that exists only because a page links to it is listed too.
			- **Batches:** 3 journals at first ([`state.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/state.cljs#L56)), then 7 more each time the scroll comes within 500px of the bottom ([`handler/page.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/handler/page.cljs#L671-L679), [`ui.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/ui.cljs#L477-L511)). An "Earlier" link sits below the last journal. On the live build, scrolling the home page six times showed 24 journals, 2026-10-24 Sat back to 2026-10-01 Thu.
			- **Each journal:** an `h1` title that links to the journal's page (`a.title.journal-title`, journal.cljs L42–56), then the whole block tree, expanded. Journals below the first render when they scroll into view.
			- **Linked References** under every journal that has any, collapsed in the encode garden because of the threshold of 0 ([`reference.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/reference.cljs#L131-L162)).
			- **Today's journal only:** the `:default-queries :journals` queries and a SCHEDULED AND DEADLINE section ([`page.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/page.cljs#L211-L226), [`scheduled_deadlines.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/scheduled_deadlines.cljs#L13-L41)). On a published site "today" is the reader's date, so these appear only when the build happens to include that day.
			- [[lsg/Ref/Logseq Published Site/Clickable Prototype]] shows four journals without references. The source and the live build show three, then batches of seven, each with Linked References.
		- ### Journal titles, pages and links
			- **Title from the file:** `journals/2026_10_23.md` is parsed as a date and re-rendered in `:journal/page-title-format` ([`extract.cljc`](https://github.com/logseq/og/blob/6e7afa8eb/deps/graph-parser/src/logseq/graph_parser/extract.cljc#L30-L63), [`block.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/deps/graph-parser/src/logseq/graph_parser/block.cljs#L273-L326)). A `title::` property would win, but no encode-garden journal has one. The default format, when the key is unset, is `MMM do, yyyy` ([`config.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/deps/graph-parser/src/logseq/graph_parser/config.cljs#L70-L76)).
			- **Links in other formats:** a page reference is treated as a journal if it parses with the configured format, `MMM do, yyyy`, `yyyy-MM-dd` or `yyyy_MM_dd` ([`date_time_util.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/deps/graph-parser/src/logseq/graph_parser/date_time_util.cljs#L15-L51)). So `[[Feb 1st, 2025]]` on `Docker/For Mac/How to Install into Zsh` opens 2025-02-01 Sat; the link text keeps the author's spelling.
			- **URL:** `#/page/2026-10-23%20fri`, the lower-cased title.
			- **Journal page:** the same layout as any page, with the title from the date and the `is-journals` class. Page properties show as on other pages (`2019-08-07 Wed` shows `logseq-entity` and `alias:: 1987`). Linked and unlinked references appear as on any page (`2026-10-23 Fri` has 1 Linked Reference, from the LangSmith question page). The namespace hierarchy section is skipped ([`page.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/page.cljs#L410-L540)).
			- **Link-only journals:** Logseq's build has 534 journal pages: the 506 files plus 28 dates that only links mention (for example `2024-11-18 Mon`, `1932-01-24 Sun`). Each is a journal page whose only content is its Linked References.
		- ### Left sidebar and shortcuts
			- The sidebar's first item is Journals (calendar icon), active on the home route; it is hidden only when `:feature/enable-journals?` is `false` and `:default-home` is set ([`container.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/components/container.cljs#L418-L438)).
			- `g j` goes to the journals feed and scrolls to the top ([`route.cljs`](https://github.com/logseq/og/blob/6e7afa8eb/src/main/frontend/handler/route.cljs#L205-L212)); with a custom home it goes to `#/all-journals` instead.
			- Logseq may create today's empty journal in the reader's browser.
	- ## What lsg publishes
		- `lsg publish --journals` publishes every file under `journals/` whose date derives from its file name as a page, titled with `:journal/page-title-format`, or `MMM do, yyyy` when the garden sets none: `journals/2026_10_23.md` is `2026-10-23 Fri`, and the same file under the default format is `Oct 23rd, 2026`. The file name is read with `:journal/file-name-format`, `yyyy_MM_dd` by default. A leading `title::` property wins over the date. [[lsg/Ref/Site Navigation]] describes the journals feed for readers.
		- Date formats accept the tokens `yyyy`, `MM`, `M`, `dd`, `d`, `do`, `MMM`, `MMMM`, `E`, `EEE` and `EEEE`, quoted literals and other literal characters, so Logseq's settings choices such as `E, MM/dd/yyyy` work. A setting with an unsupported token falls back to the default with a diagnostic naming the setting.
		- Journals follow the same public rules as pages: a journal with `public:: false` is withheld, and in a garden without `:publishing/all-pages-public? true` only journals marked `public:: true` publish. A journals file whose name is not a real date is skipped with a diagnostic and counted in `skipped_journals`. Without `--journals`, journals are counted and skipped.
		- A journal page shows its blocks, page properties and Linked References as other pages do, accepts its aliases as link targets, and has no Hierarchy section: `2026-10-23 Fri` shows its Filed and Updated blocks and 1 Linked Reference, and a link to `1987` opens `2019-08-07 Wed`. Journal pages appear in the All pages list and in search.
		- A page reference that matches no title or alias resolves to the journal with its date when it parses in the configured title format, `MMM do, yyyy`, `yyyy-MM-dd` or `yyyy_MM_dd`, tried in that order. Month and weekday names match without regard to case, and a weekday that contradicts the date fails. `[[Feb 1st, 2025]]` opens `2025-02-01 Sat` and keeps its text. Embeds, favorites and the homepage selector resolve dates the same way.
		- With journals published, `index.html` is the journals feed and the All pages list moves to `pages.html`. With `--homepage`, the feed starts at `journals.html`. The feed lists published journals dated on or before the build date, newest first: three in the first file, then seven in each `journals-2.html`, `journals-3.html` and onward. The build date is the UTC date of `SOURCE_DATE_EPOCH` when it is set and of the system clock otherwise; later-dated journals keep their pages and stay out of the feed.
		- Each journal in the feed has an `h1` linking to its page, its block tree with its authored collapse state, and, when it has Linked References, a collapsed section with their count. Each batch with a later batch ends with an Earlier link to it.
		- `lsg-journals.js` loads after the page's `load` event. When the Earlier link comes within 500px of the viewport, it fetches the next batch file, appends its journals and points Earlier at the following batch. Without JavaScript, Earlier opens the batch file. Opening a journal's Linked References in the feed fetches the journal page and shows its Linked References with working filters.
		- For garden commit `09cf7fb` with a build date of 2026-10-25, `index.html` lists `2026-10-24 Sat`, `2026-10-23 Fri` and `2026-10-22 Thu`, as Logseq's build does; scrolling to the bottom once shows ten journals, through `2026-10-15 Thu`.
		- When a feed is published, Journals is the left sidebar's first item, with a calendar icon; it links to the feed's first file and is marked current on every feed file. `g j` opens the feed. A garden with `:feature/enable-journals? false` gets journal pages and no feed, and `index.html` is the All pages list.
		- The SDK's `journals` module reads the date formats, derives each journal's date and title, recognises journal references and lists journals newest first, and `PageNameIndex::with_journal_formats` resolves date references in every lookup; it adds no date library. The publisher writes the journal pages, the feed and its batch files, `lsg-journals.js`, the sidebar item and `g j`.
		- Measured on 2026-10-26 with `lsg` `b490d68` on the whole encode garden at commit `0ce74d6`: the home page showed its title in 21.0 ms on desktop and 242 ms on the phone profile, with 12.3 KB of data before it, where Logseq's took 20,937 ms and 204,698 ms. After ten later batches the feed showed 73 journals, with a peak JavaScript heap of 4.6 MB on desktop and 3.1 MB on the phone profile; Logseq still showed 3 journals after 30 seconds, with a heap of about 2 GB. A whole-garden build with `c373d90` on garden commit `083106d` took 10.4 seconds without journals and 10.5 seconds with them. [[lsg/Ref/Logseq Compatibility/Performance]] holds every row, and the `[journals]` table of [`scripts/parity/budgets.toml`](https://github.com/codekiln/logseq-gardener/blob/main/scripts/parity/budgets.toml) holds the budgets: `lsg-journals.js` at most 4 KB, at most 20 MB of phone heap after ten batches, and a build with journals at most 20% slower than one without. `parity:budgets` also checks that adding 1,000 older journals leaves `index.html` the same size.
	- ## Differences from Logseq
		- `lsg` publishes journals only with `--journals`. Its selection starts from nothing and adds what the build names, so existing builds such as Gitpa's gain no daily notes they did not ask for. `parity:build` passes the flag, so the encode garden matches Logseq.
		- The feed lists journals dated on or before the build date, which a build can pin with `SOURCE_DATE_EPOCH`. Logseq uses the reader's date, which a static page cannot apply without loading the journal list in the browser, so the newest journal in the feed can be a day off Logseq's.
		- Later journals come from static batch files of seven, so every batch has a plain address and works without JavaScript.
		- Linked References under a feed journal show only their count until the reader opens them, then load from the journal's page. Logseq renders them with the journal, collapsed in the encode garden.
		- Today's `:default-queries` and the SCHEDULED AND DEADLINE section are left out. A static build cannot know the reader's date, and showing them for the build date would show stale tasks as today's.
		- `lsg` publishes no page for a date that only links mention, such as `2024-11-18 Mon`; a link to it renders as unresolved text, so no link leads to a missing file. Logseq's build has 28 such journal pages, among the pages that exist only because something references them.
		- A journals file whose name is not a date is skipped. Logseq publishes it as an ordinary page.
		- The homepage comes from `--homepage`; `lsg` does not read `:default-home {:page …}`. With a homepage, the Journals item and `g j` open `journals.html`, where Logseq opens `#/all-journals`.
		- A static site cannot create today's empty journal.
	- ## Before the change
		- The `lsg` build measured on 2026-10-25, from `ac32058`, published no journals.
		- `publish_site_with_options` counted and skipped every file under `journals/` (`site/mod.rs`, `skipped_journals: 505`). `page_title` returned `UnsupportedJournal` for journals because it had no date format.
		- `GardenSettings` read `:feature/enable-journals?` but not `:journal/page-title-format`, `:journal/file-name-format` or `:default-home`.
		- `index.html` was the full page list (1,230,364 bytes for the whole garden) unless `--homepage` named a page, in which case the list moved to `pages.html`.
		- Links to journal titles rendered as `<span class="unresolved">` with a diagnostic: 778 of the 16,108 "Unresolved or excluded page reference" diagnostics named a `yyyy-MM-dd EEE` title.
		- The app shell had no Journals sidebar item and no `g j`.
