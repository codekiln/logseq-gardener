- # Selection and Visibility Reference
	- ## Overview
		- `lsg publish` follows Logseq's publishing rules within the namespaces you select. `--include` and `--exclude` choose the selected pages, the visibility rules decide which selected pages are published, and references, aliases and embeds resolve only against that published content.
		- Mixed-visibility fixtures in the [publisher tests](https://github.com/codekiln/logseq-gardener/blob/main/crates/logseq-gardener-sdk/tests/site.rs) and the [embed tests](https://github.com/codekiln/logseq-gardener/blob/main/crates/logseq-gardener-sdk/tests/site_embeds.rs) check the generated files for excluded content. Diagnostics stay outside the site. Review the report and the content of the retained source pages before you publish a sensitive garden.
	- ## Namespace selection
		- The SDK's `publishing::NamespaceSelection` selects logical page names with included and excluded namespace roots. `--include` and `--exclude` pass their values to it.
		- A root selects itself and its descendants separated by `/`: `My/AI` selects `My/AI/Rule`, and `My/AIM` stays outside the selection.
		- Exclusions take precedence over inclusions. An empty inclusion list selects nothing.
		- `--include-all` selects every page instead, through the selection's `including_all()`. Exclusions still apply, and pages it selects follow the same visibility rules, so withheld pages stay withheld.
		- Matching is exact and case-sensitive.
		- Selectors match logical page titles, which come from the configured file name format and leading `title::` properties. [[lsg/Ref/Page Titles]] describes the title rules. Names are not file system paths.
		- Aliases help resolve references. They do not select a page into a namespace.
		- An empty selector, an empty namespace segment, whitespace around a segment and a control character produce constructor errors; `lsg publish` exits 2. A malformed candidate page name is left unselected.
	- ## Published pages
		- When `logseq/config.edn` sets `:publishing/all-pages-public? true`, or the older `:all-pages-public? true`, every selected page is published.
		- Otherwise, as in Logseq, only selected pages whose leading properties set `public:: true`, and pages that name such a page with `alias::` or that such a page names with `alias::`, are published. The report counts the other selected pages as withheld and names each one in a diagnostic. The SDK's `publishing::PublicPages` applies this rule.
		- A garden without `logseq/config.edn` publishes every selected page.
		- In every case:
			- A page with any parsed `public:: false` property is withheld as a whole, including a page where only a child block in the outline sets it.
			- A `public:: true` page outside the selected namespaces stays out.
			- Content nested more than 64 levels deep withholds its page.
		- Journals follow the same visibility rules as pages when `--journals` publishes them. `--include` and `--exclude` do not apply to journals.
		- Visibility also applies to embedded content, referenced assets, reference indexes and search data.
	- ## Publication boundaries
		- The publisher resolves page titles, aliases, explicit outline references and page and block embeds against selected visible content only.
		- A namespace exclusion removes its pages and everything they contribute, such as embedded content and references. It does not redact text already written on a retained page.
		- An ambiguous or unavailable target keeps a visible fallback in the page and gets a diagnostic. A block embed renders nothing in its place.
	- ## Hierarchy destinations
		- Hierarchy destinations come only from the original titles of selected visible pages. A page whose title has no `/` and no descendants takes its Hierarchy rows from its first namespaced alias, and that alias creates no destination.
		- An ordinary unselected ancestor may get a navigation-only page. Its body, aliases, properties and assets stay outside the publication.
		- A stored private or visibility-withheld ancestor gets no generated destination, even when it is outside the include roots. Its segment stays plain text in each visible full-path row, and the available prefixes keep their links.
		- A generated prefix that conflicts with a selected alias is also left unlinked.
		- Aliases keep their source lookup behaviour and create no namespace branches.
		- [[lsg/Ref/Published Pages]] describes the Hierarchy section and generated namespace pages.
	- ## Page references
		- A page reference can use a selected page's title or one of its leading aliases.
		- Name matching ignores letter case, surrounding whitespace and a slash at either end. It also treats equivalent Unicode spellings of accented letters as equal, using Normalization Form C (NFC).
		- Duplicate selected titles fail the build before the output directory is created. A file outside `pages/` and `journals/` whose title repeats the title of a file in those folders is skipped with a diagnostic instead.
		- A reference to a withheld, unselected or ambiguous name keeps the label written in the selected source and gets a diagnostic.
		- A page reference or tag to a generated namespace page links to it with the Namespace link style.
	- ## Reference-only pages
		- As in Logseq, a name that a published block links, tags or lists in `tags::` or another page-valued property becomes a page even when no file holds it. `[[Deno Deploy]]` on a published page publishes a page titled `Deno Deploy` that shows its Pages tagged with, Linked References, Hierarchy and Unlinked References. Each namespace parent of such a name becomes one too, unless it is already a generated namespace page.
		- A reference-only page is published whatever the `--include` selection, because it has no file for the selection to choose: publishing `--include Deno` publishes `Deno Deploy`.
		- A name that any page or journal file has as its title, alias or date never becomes a reference-only page, whether that file is published, withheld or outside the selection, so those references stay unresolved. A name that only withheld or unselected pages write, or that a published page writes only in a property that `:block-hidden-properties` hides, gets no page. A file that `:hidden` hides counts as no file.
		- Task markers, priorities, block UUIDs and asset paths make no page.
		- The page takes the spelling of the first reference Logseq reads: journals newest first, then other files by path, and within a file the spelling Logseq's parser keeps. A name that spells a date takes the journal title format's title and is listed as a journal.
		- A page whose address collides with another page or with a file the build writes at the output root, such as `Assets/Logo` with `--readable-urls`, is left out with a diagnostic, and references to it stay unresolved.
		- Markdown links to page file names are not resolved; they keep a visible fallback and get a diagnostic.
	- ## Aliases
		- Only the last leading `alias::` property of a page is used. It accepts comma-separated plain names and direct page references.
		- A quoted or wholly literal value keeps its literal spelling. Nested properties and `aliases` metadata supply no page aliases.
		- Competing visible claims to one name, including an alias that matches another page's title, keep the source label and get an ambiguity diagnostic.
		- Claims from withheld pages never enter the lookup.
		- Routes and namespace selection use the page's original logical title, never an alias.
	- ## Block references and embeds
		- A reference to a unique explicit `id::` UUID on a published Markdown outline block links to that block. Its default label is the target block's first line, with its inline markup, task checkbox and heading; a label written in the source takes precedence. An ordinary block reference provides navigation.
		- When several blocks give the same `id::`, the block Logseq reads first keeps it: journal files from the last path to the first, then files whose path holds `contents.`, then other files by path, and within a file the first block. The other blocks lose the id.
		- Page and block embed macros insert selected visible content, including the descendants of an embedded block, with the embedded document's own asset paths.
		- References and embeds share Logseq's nesting limit of 5 levels. Past it, an embed shows `Embed depth is too deep` and a reference shows `Block ref nesting is too deep`.
		- A page embed of the page itself, or of a page already being embedded, renders only its header. Expansion also stops after 128 expansions or 10,000 embedded syntax tree nodes per output document.
		- Repeated copies of a block leave out its original ID, so block links still open the original page.
		- A block reference whose target is missing, excluded, private, invalid or unsupported shows its `((uuid))` source as a warning titled `Block ref invalid`. An unavailable or ambiguous block embed renders nothing, and an unavailable or ambiguous page embed shows its frame and a header with the page name as plain text, with no body. Each gets a diagnostic.
		- A query that does not parse or cannot run shows Logseq's query error, with a diagnostic. A query inside an embed or a block reference stays literal.
		- IDs in a page's root properties are not outline targets.
