## Why

Merged implementations remain listed as active OpenSpec changes, and their requirements can remain absent from main specs. A cleanup sub-issue gives contributors a visible follow-up that ends with synchronized requirements and an archived change.

## What Changes

- Require a GitHub cleanup sub-issue under each implementation issue, linked to the implementation PR and exact OpenSpec change.
- Document post-merge verification, inline spec synchronization, archival, and a separate follow-up PR from current main.
- Explain reuse of existing cleanup work and handling of overlapping requirements when main advances.
- Link the guide from CONTRIBUTING and generated agent instructions.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `project-workflow`: Track and complete OpenSpec cleanup after the implementation PR merges.

## Impact

Contributor documentation, RuleSync source and generated instructions, GitHub issue relationships, and the project-workflow specification. Existing OpenSpec skills continue to perform verification, synchronization, and archival.
